================================================================================
                    LOAD VALUE PREDICTOR (LVP) FLOW DOCUMENTATION
================================================================================

This document describes the complete flow of a load instruction through the
Load Value Predictor (LVP) in gem5's O3 CPU model.

================================================================================
OVERVIEW OF LVP COMPONENTS
================================================================================

1. Load Classification Table (LCT)
   - Files: src/cpu/lvp/load_classification_table.{cc,hh}
   - Purpose: Classifies loads by PC using saturating counters
   - Returns: LVPType (UNPREDICTABLE, PREDICTABLE, or CONSTANT)
   - Like: Branch predictor (2-bit saturating counters)

2. Load Value Prediction Table (LVPT)
   - Files: src/cpu/lvp/load_value_prediction_table.{cc,hh}
   - Purpose: Stores predicted values for loads
   - Returns: RegVal (actual predicted value, e.g., 49, 4096)
   - Like: Branch Target Buffer (tag-indexed value storage)

3. Constant Verification Unit (CVU)
   - Files: src/cpu/lvp/constant_verification_unit.{cc,hh}
   - Purpose: Tracks constant loads in a CAM, invalidates on store conflicts
   - Structure: Fully-associative CAM storing (PC, load_addr, LVPT_index)

4. Load Value Prediction Unit (LVP)
   - Files: src/cpu/lvp/load_value_prediction_unit.{cc,hh}
   - Purpose: Top-level coordinator that interfaces with all components
   - Provides: Main API for CPU to interact with predictor

================================================================================
KEY DATA STRUCTURES
================================================================================

1. LVPT Entry (load_value_prediction_table.hh:34-51)
   struct LVPTEntry {
       Addr tag;           // Upper bits of PC for tag matching
       RegVal target;      // Predicted load value (e.g., 49, 4096)
       ThreadID tid;       // Thread ID
       bool valid;         // Entry valid flag
   }

2. LCT Counter (load_classification_table.hh:92)
   std::vector<SatCounter8> localCtrs
   - 2-bit saturating counters (default)
   - Indexed by PC
   - Counter states:
       0: STRONG_UNPREDICTABLE
       1: WEAK_UNPREDICTABLE
       2: PREDICTABLE
       3: CONSTANT (saturated)

3. CVU CAM Entry (constant_verification_unit.hh:70-76)
   struct CAMEntry {
       Addr lvpt_index;      // Index in LVPT
       Addr pc;              // Load PC
       Addr load_address;    // Load memory address
       TimePoint entry;      // Entry creation time
       TimePoint access;     // Last access time (for LRU)
   }

4. LVP Classification Types (base/types.hh)
   enum LVPType {
       LVP_STRONG_UNPREDICTABLE = 0,
       LVP_WEAK_UNPREDICTABLE = 1,
       LVP_PREDICTABLE = 2,
       LVP_CONSTANT = 3
   }

================================================================================
IMPORTANT IMPLEMENTATION NOTES
================================================================================

1. LVPT Index Calculation (load_value_prediction_table.cc:62-68):
   index = ((PC >> instShiftAmt) ^ (tid << (tagShiftAmt - instShiftAmt - log2NumThreads))) & idxMask
   - instShiftAmt = 2 (shift off lower 2 bits)
   - tagShiftAmt = instShiftAmt + log2(numEntries)
   - log2NumThreads = 0 (single thread)
   - idxMask = numEntries - 1

2. LVPT Tag Calculation (load_value_prediction_table.cc:73-75):
   tag = (PC >> tagShiftAmt) & tagMask
   - tagMask = (1 << tagBits) - 1 = 0x3FF (10 bits)

3. LCT Index Calculation (load_classification_table.cc:160-162):
   index = (PC >> instShiftAmt) & indexMask
   - instShiftAmt = 0 (no shift)
   - indexMask = localPredictorSets - 1

4. Critical Bug Fixes Applied:
   a) log2NumThreads was uninitialized → Fixed by setting to 0
   b) LVPT valid() didn't check tag → Fixed by adding tag comparison
   c) lvptResultValid not set to false → Fixed by setting in else branch
   d) LCT only consulted if LVPT valid → Fixed by always consulting LCT
